## Goal

The factory DB has the tables v0 needs for projects, repositories, runs, steps and events, created by an Alembic migration.

## Read first

- `CLAUDE.md`
- `docs/spec/05-domain-model.md`
- `docs/spec/10-observability.md` (How data flows, What is measured)
- `core/src/fact/core/db.py`

## Do

- `fact/core/models.py`, typed SQLAlchemy models (`Mapped[...]`) using only Postgres-compatible types (`String`, `Text`, `Integer`, `Numeric(12, 6)` for USD, `DateTime(timezone=True)`, `JSON`):
  - `Project`: `id`, `name` (unique), `home_repo`, `created_at`.
  - `Repository`: `id`, `project_id`, `full_name` (`owner/repo`), `role`, `default_branch`, `merge_order`.
  - `Run`: `id` (string, uuid4 hex), `workflow_id` (`run-<task key>-<n>`, unique), `project_id`, `task_key`, `workflow_type`, `status` (queued, running, waiting, finished), `outcome` (nullable), `complexity`, `worker_version`, `home_sha`, `created_at`, `started_at`, `ended_at`, and totals: `machine_seconds`, `human_wait_seconds`, `tokens_in`, `tokens_out`, `cost_usd`, `human_touches`.
  - `Step`: `id`, `run_id`, `stage_id`, `kind` (agent, shell, github, gate, notify), `attempt`, `status`, `outcome`, `harness`, `model`, `queued_at`, `started_at`, `ended_at`, `wait_seconds`, `tokens_in`, `tokens_out`, `cost_usd`, `log_ref`, `transcript_ref`, `outputs` (JSON). Unique on (`run_id`, `stage_id`, `attempt`).
  - `Event`: `id`, `run_id`, `step_id` (nullable), `type`, `at`, `payload` (JSON).
- Enums are `StrEnum`s stored as strings, defined in `fact/core/enums.py` (`RunStatus`, `StepKind`, `StepStatus`, `StepOutcome` with the seven outcomes from the spec).
- One Alembic revision, autogenerated and then read through.
- Tests: migrate a fresh DB; insert a project, a run with two steps and an event; check the unique constraint on step attempts.

## Out of scope

- Any API on top of these tables (M0-08, M1-03).
- Notifications table (M2-03).

## Acceptance criteria

- [ ] `uv run pytest core` passes, including the insert and constraint tests.
- [ ] `alembic check` (or the equivalent autogenerate comparison in a test) reports no drift between models and migrations.
- [ ] No SQLite-only column types.
