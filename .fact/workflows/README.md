# Workflows

This project's workflow code (`*.py`), loaded by its workflow worker from a checkout of this repository. Each workflow subclasses `FactWorkflow` from `fact.sdk.workflow`, declares its stages with `@stages([...])` and imports shared types from `fact.sdk.types`.

- `standard.py`: `Standard` (Temporal type `standard`). Prepare the workspace, run `implement`, loop lint and test with `fix_checks` sessions (at most 3) until green, then one `review` session (stage `review`, opus via `fact.yaml` routing) against the acceptance criteria and the repository's rules. If a criterion is unmet or a finding is medium or high, an `address_review` session fixes them and the check loop runs again (one review round in v0). Then a `learn` session updates `CLAUDE.md`, `docs/` and READMEs on the branch and writes the PR title and summary (falling back to the implement session's, then the task title, when it gives none or does not pass); mark the task done on the branch, open the PR with the review's criteria table and comment the run's cost on it. Then `until_ci_green` waits for CI on the PR's head commit (stage `wait_for_ci`); a failure goes to a `fix_ci` session with the failing jobs' links and log tails, whose commit is pushed to the PR (the next `open_pr` attempt) before CI is awaited again, at most `MAX_CI_FIX_ATTEMPTS` (2) times. The cost comment is updated at the end. `agent` resumes a session once when the worker stopped during it or the agent reports a temporary, retryable block (see `fact.sdk.sessions`). Outcomes: `pr_opened` (CI green); `needs_human` (an agent reported itself blocked, or checks never went green: no PR; or CI stayed red, a CI fix was blocked or committed nothing, or CI never finished: PR open, workspace kept); `failed` (an agent session errored or hit its turn limit, including a review without a valid structured answer).

Workflow code is replayed by Temporal: no I/O, clock or settings reads; timeouts come from `RunInput.limits`. `uv run pytest worker/tests/test_standard_workflow.py` replays a fresh green run to check the workflow stays deterministic.

`python -m fact.worker` loads these files from a detached checkout of the default branch's SHA (`pinned_dir/projects/<project>/<sha>`) and runs them on task queue `wf-<project>`, pinned to that version (see `worker/README.md`). Files starting with `_` are skipped; a file that fails to import stops the whole project from loading. Only classes that subclass `FactWorkflow` and are decorated with `@workflow.defn` themselves are registered. A change merged to the default branch takes effect at the next worker restart; runs already pinned to the old version then wait until they are dropped and restarted.
